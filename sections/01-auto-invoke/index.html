01　自動で呼ばれる（/ なし）

資料 P2・P4・P7
このセクションのゴール
Skill の名前を言わずに「レビューして」「調査して」と頼むだけで、Claude が適切な Skill を選んで使うことを確かめる。

準備

プロジェクトルートから、次のコマンドでこのセクション専用の環境を起動する。

ターミナル
cd sections/01-auto-invoke && claude
このセクションの中身
.claude/skills/
├── local-review/SKILL.md   ローカルのファイルや差分をレビューする
└── investigate/SKILL.md    コードを読み取り専用で調べる
sample/                      題材（電卓）。わざと不備が入っている

やってみる

  1. 見えている Skill を確認

    Claude に入力
    /skills
    期待する結果　local-review と investigate が Project として見える（直下の pr-review も見える）。

  2. Skill 名を言わずに、レビューを頼む

    Claude に入力
    sample/src/calculator.ts をレビューして
    期待する結果　出力の先頭に [local-review 起動] が出る。指摘の表に、average（空配列）、percentOf（0 除算）、テスト不足などが挙がる。

    起動マーカーは、各 Skill の本文に「最初にこの一言を出す」と書いてあるだけ。起動したかが見た目で分かるようにしている。

  3. 調査を頼む

    Claude に入力
    割り算の処理がどこにあるか調査して
    期待する結果　[investigate 起動] が出て、sample/src/calculator.ts の行番号つきで報告される。ファイルは編集されない。

  4. （参考）サンプルに入っている不備

    期待する結果　題材の sample/ には、レビューや調査で見つけてもらうために、わざと不備を入れてある（下の一覧）。レビュー結果に出てきたら、狙いどおり。

    average([]) は NaN を返す／percentOf(x, 0) は Infinity を返す（divide だけが 0 除算を検査していて一貫しない）／parseNumber("abc") は NaN を返す／テストは add と divide の正常系だけ（テストが少ないのも意図。「テスト不足」を指摘させるため。このサンプルは CI の対象外）。

  5. 対象外の依頼では呼ばれない

    Claude に入力
    こんにちは。今日の調子はどう？
    期待する結果　どの Skill も起動しない（マーカーが出ない）。

  6. 言い換えても呼ばれるか試す

    Claude に入力
    calculator.ts のコード、問題ないか見てくれる？
    Claude に入力
    average はどこから呼ばれている？
    期待する結果　1つ目は local-review、2つ目は investigate が選ばれることが多い。

    Claude が description と依頼を照合して選んでいる。毎回同じとは限らない（P9）。外れたら、言い換えて何度か試す。

local-review/SKILL.md の frontmatter（抜粋）
---
name: local-review
description: ローカルのファイル・未コミットの差分・ブランチの差分をレビューし、問題点を重要度付きで報告する。「レビューして」「コードを見て」「問題がないか確認して」と言われたときに使う。PR（プルリクエスト）のレビュー、コードの新規実装・修正には使わない。
---

ここがポイント

  • 一度も Skill 名を打っていない。Claude は起動時に全 Skill の description だけを読み、依頼と照合して選ぶ。
  • 直下の pr-review も一覧に見えているが、「レビューして」には、ローカルのファイルを対象にした local-review が選ばれた（この教材での確認結果）。local-review の description に「PR のレビューには使わない」と書いてあるため。
  • investigate には allowed-tools: Read Grep Glob を付けてある。調査の Skill が勝手にファイルを書き換えないようにする狙い（セクション 04・11 で詳しく）。

うまくいかないとき

  • 起動しない → 新しいセッションで試す。同じ会話では前の文脈が残って結果に影響する。
  • 起動マーカーが出ない → /skills に出ているか確認。出ていなければ、起動したディレクトリが違う。
  • 結果が毎回違う → 仕様。LLM の判断なので、1回の成功で「うまくいった」と判断しない。

LLM の判断で動くため、結果は毎回同じとは限らない。「期待する結果」はこの教材で確認した例。違う結果になっても、言い換えて何度か試す。
