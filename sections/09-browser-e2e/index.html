09　ブラウザ打鍵（MCP）

所要 20分資料 P1（MCP の活用）
このセクションのゴール
Playwright MCP で、Claude に実際のブラウザを操作させ、電卓アプリを打鍵させる。自動で呼ばれる版と、手動専用の固定シナリオ版を比べる。

準備

先に、リポジトリ直下で開発サーバーを起動しておく（別のターミナルで起動したままにする）。

ターミナル
pnpm install
ターミナル
pnpm dev

リポジトリ直下から、次のコマンドでこのセクション専用の環境を起動する。

ターミナル
cd sections/09-browser-e2e && claude
このセクションの中身
.mcp.json                                  Playwright MCP を宣言
.claude/skills/
├── e2e-calculator/SKILL.md    自動で呼ばれる。指定された計算を打鍵
└── smoke-test/SKILL.md        手動専用。固定の 6 件を順に打鍵

やってみる

  1. MCP サーバーが認識されているか確認

    Claude に入力
    /mcp
    期待する結果　初回は、プロジェクトの .mcp.json を使うかの確認が出る。許可すると playwright が connected になる。

  2. 打鍵を頼む（自動で呼ばれる版）

    Claude に入力
    画面で動作確認して。10 ÷ 0 だけ試して
    期待する結果　ブラウザが開き、e2e-calculator が使われる。10 ÷ 0 を入力して計算し、0 で割ることはできません が表示されるのを確認して、表で報告する。

    Playwright の操作ツールの許可を求められたら許可する。初回にブラウザが無いと言われたら、案内に従ってインストールする。

  3. 固定シナリオを実行する（手動専用）

    Claude に入力
    /smoke-test
    期待する結果　6 件を順番どおりに打鍵し、表と「合格 N / 6」が出る。6 件目（0.1 + 0.2）は 0.30000000000000004 と表示され、NG になる想定。

    これは Skill の失敗ではなく、浮動小数点の誤差による「打鍵で見つかる不具合」の例。ユニットテストでは気づきにくい、画面の表示に出る問題。

ここがポイント

  • 壊れやすい操作ほど自由度を下げる（P8）。smoke-test は順番と入力値を固定し、e2e-calculator は依頼に応じて動く。
  • allowed-tools: mcp__playwright は、その Skill で Playwright のツールだけを承認なしで使えるようにする宣言。ファイル編集は含まない。
  • MCP の権限は広くなりやすい。外部由来の Skill が MCP を使う場合は、監査の対象（セクション 11、P12）。

うまくいかないとき

  • 画面につながらない → pnpm dev を起動しているか。http://localhost:5173 をブラウザで開けるか確認する。
  • npx がない → Node.js をインストールする。
  • ブラウザが起動しない → npx playwright install chromium を試す。

LLM の判断で動くため、結果は毎回同じとは限らない。「期待する結果」はこの教材で確認した例。違う結果になっても、言い換えて何度か試す。
