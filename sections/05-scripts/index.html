05　scripts で検査を自動化

資料 P6・P8
このセクションのゴール
「文章で守れ」と書いても守られないルールを、スクリプトで機械的に判定させる。AI の判断と、決まった検査の役割分担を体験する。

準備

プロジェクトルートから、次のコマンドでこのセクション専用の環境を起動する。

ターミナル
cd sections/05-scripts && claude
このセクションの中身
.claude/skills/ui-contrast/
├── SKILL.md                         判断が要る部分（いつ・どう直すか）
└── scripts/validate_colors.py       数値で判定する部分（実行するだけ）
sample/style.css                     検査される CSS（わざと読みにくい色がある）

やってみる

  1. まず、スクリプトを手で動かす（Claude 抜き）

    ターミナル
    python3 .claude/skills/ui-contrast/scripts/validate_colors.py "#999999" "#ffffff"; echo "exit=$?"
    ターミナル
    python3 .claude/skills/ui-contrast/scripts/validate_colors.py "#2563eb" "#ffffff"; echo "exit=$?"
    期待する結果　1 つ目: 2.85:1 → FAIL（終了コード 1）と「次の行動」が出る。2 つ目: 5.17:1 → AA PASS / AAA FAIL（終了コード 0）。

    終了コードで 合格 0 / 不合格 1 / 入力エラー 2 を区別している。「入力ミス」と「不合格」を混同させないための作法（P8）。

  2. Claude に配色の確認を頼む

    Claude に入力
    sample/style.css の配色を確認して
    期待する結果　[ui-contrast 起動] が出る。.lead（#999999 on #ffffff）が FAIL になり、色を暗くして再検証し、PASS を確認してから完了する。

    Python の実行や CSS の編集で許可を求められたら、内容を読んでから許可する。

  3. 結果を確かめて、元に戻す

    ターミナル
    git diff -- sample/style.css
    ターミナル
    ../sync-sample.sh
    期待する結果　#999999 が濃い色に変わっているのが見える。sync-sample.sh でサンプルが元に戻る。

整理

種別置き場所例
判断が要る規約SKILL.md / references/トーン、余白の考え方
数値で判定できる規約scripts/（実行）コントラスト比、フォントサイズの下限
成果物の雛形assets/トークン定義、テンプレート

ここがポイント

  • SKILL.md に「実行する（読むのではなく）」と明記する。読み込んでしまうと、コードがコンテキストに入るだけになる。
  • ${CLAUDE_SKILL_DIR} は Skill のディレクトリに置き換わる Claude Code の変数。claude.ai / API では使えない。
  • HEX は必ず引用符で囲む。# 以降がシェルのコメントになり、引数が消えるため。
  • FAIL のまま完了させない。出力に「暗くして再検証」と書き、Claude がそのまま修正に移れるようにする。

うまくいかないとき

  • python3 が実行できない → Python 3 をインストールする（標準ライブラリのみ使用）。
  • Claude が「手計算した」と言う → スクリプトを実行する許可が出ていない可能性。許可して再度頼む。

LLM の判断で動くため、結果は毎回同じとは限らない。「期待する結果」はこの教材で確認した例。違う結果になっても、言い換えて何度か試す。
