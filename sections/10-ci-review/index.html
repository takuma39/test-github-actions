10　CI から Skill を呼ぶ

所要 15分資料 P1（ワークフロー）・P12
このセクションのゴール
PR を作ると GitHub Actions がテストを実行し、Claude を起動して、/pr-review の Skill でレビューコメントを投稿する流れを理解する。

準備

このセクションはローカルでは動かさず、GitHub 上で確かめる。

このセクションの中身
.github/workflows/test.yml              PR / main への push でテスト・型チェック・ビルド
.github/workflows/claude-review.yml     PR の作成・更新で Claude を起動
.claude/skills/pr-review/SKILL.md         レビューの手順・観点・やらないこと

やってみる

  1. まず、テストの CI（Test）を読む

    ターミナル
    cat .github/workflows/test.yml
    期待する結果　main 宛ての PR の作成・更新、および main への push で動く。Node.js 22 で、下の表の 4 つを順に実行する。

    pnpm のバージョンは package.json の packageManager で固定され、pnpm/action-setup がそれを読み取る。concurrency の設定により、同じ PR に連続で push すると、古い実行は自動でキャンセルされる。

  2. Claude によるレビューのワークフローを読む

    ターミナル
    cat .github/workflows/claude-review.yml
    期待する結果　トリガーは PR の opened / synchronize。prompt に /pr-review <リポジトリ>/pull/<番号> を渡して Skill を呼んでいる。

  3. Skill の中身を読む

    ターミナル
    cat .claude/skills/pr-review/SKILL.md
    期待する結果　手順（差分の取得 → 必要なら周辺を読む → PR に投稿）、レビュー観点、やらないことが書かれている。

  4. PR を作って、結果を見る（Test と Claude Review の両方）

    GitHub 上で、test/error（または自分の作業ブランチ）から main 宛ての PR を作る。gh コマンドがあれば、gh pr create --base main --head test/error でもよい。

    期待する結果　PR 画面の下部に「Test」のチェックが表示され、Actions の Claude Review が走って、PR に日本語のレビューコメントが付く。

整理

順Test の実行内容目的
1pnpm install --frozen-lockfilepnpm-lock.yaml どおりに依存をインストールする
2pnpm run typecheck型エラーがないか確認する
3pnpm testVitest でテストを実行する
4pnpm run build本番ビルドが通るか確認する

ここがポイント

  • リポジトリの Settings → Branches でブランチ保護ルールを追加し、Test を必須チェックにすると、テストが通らない限りマージできなくなる。
  • Skill は CI でも使える。ただし .claude/skills/ を読ませるため、actions/checkout が必要。差分を取るので fetch-depth: 0 も要る。
  • --allowedTools を渡さないと、Claude はコメントを投稿できず、レビュー結果を出力しただけで正常終了する（ワークフローのコメントにも書いてある）。権限は必要最小限（gh pr comment、git diff など）。
  • --max-turns が小さいと、レビューが途中で打ち切られる。SKILL.md に「往復回数には上限がある。無駄な確認を挟まない」と書いて、手順を絞っている。
  • このリポジトリ直下の .claude/skills/pr-review は、全セクションに継承される。CI のために残してある。

うまくいかないとき

  • コメントが付かない → Actions のログと、トークン・権限（pull-requests: write）を確認する。
  • Draft PR は対象外（ワークフローの if 条件）。

LLM の判断で動くため、結果は毎回同じとは限らない。「期待する結果」はこの教材で確認した例。違う結果になっても、言い換えて何度か試す。
