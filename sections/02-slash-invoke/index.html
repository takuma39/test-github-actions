Skills ハンズオン / セクション 02

02　/ で呼ぶ（手動）

資料 P4・P10
このセクションのゴール
同じ Skill を、/名前 で明示的に呼ぶ。自動起動との違い（確実に起動する・引数を渡せる）を確かめる。

準備

プロジェクトルートから、次のコマンドでこのセクション専用の環境を起動する。

ターミナル
cd sections/02-slash-invoke && claude
このセクションの中身
.claude/skills/
├── local-review/SKILL.md   01 と同じ Skill
└── investigate/SKILL.md    01 と同じ Skill

やってみる

  1. 候補を見る

    Claude に入力
    /
    期待する結果　/ だけ打つと、呼び出せる Skill の候補が出る。local-review には引数のヒント [ファイルパス] が表示される（argument-hint）。

  2. 引数つきでレビューを呼ぶ

    Claude に入力
    /local-review sample/src/calculator.ts
    期待する結果　必ず [local-review 起動] が出る。引数のファイルが対象になる。

  3. 引数つきで調査を呼ぶ

    Claude に入力
    /investigate average が空配列のときの扱い
    期待する結果　[investigate 起動] が出て、average の挙動が根拠つきで報告される。

  4. 01 との違いを比べる

    期待する結果　下の表のとおり。自動は便利だが「選ばれるか」は確実でない。手動は確実だが、人が覚えて打つ必要がある。

整理

自動（01）手動（02）
起動のきっかけ依頼の内容と description の一致/名前 を打つ
確実さ外れることがある必ず起動する
引数文章から Claude が読み取る$ARGUMENTS に入る
向いている作業規約・レビュー手順などデプロイ・コミットなど副作用のある操作（04）

ここがポイント

  • Skill は「Claude が自動で使う知識」でもあり、「人が /名前 で呼ぶコマンド」でもある。旧 commands/ は Skill に統合済み（P10）。

うまくいかないとき

  • 候補に出ない → /skills で確認。起動したディレクトリが違う可能性がある。

LLM の判断で動くため、結果は毎回同じとは限らない。「期待する結果」はこの教材で確認した例。違う結果になっても、言い換えて何度か試す。
