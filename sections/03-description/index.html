03　description で決まる

資料 P7・P9
このセクションのゴール
description の書き方で、Skill が呼ばれるかどうかが変わることを体験する。悪い description を自分で直し、再テストする。

準備

プロジェクトルートから、次のコマンドでこのセクション専用の環境を起動する。

ターミナル
cd sections/03-description && claude
このセクションの中身
.claude/skills/
├── investigate/SKILL.md    description が「調査」の1語だけ（悪い例）
└── local-review/SKILL.md   description が「コードをレビューする」だけ（短い例）
answer/                      正解例（Claude には読み込まれない場所）

やってみる

  1. 悪い description の Skill に、調査を頼む（5本）

    Claude に入力
    割り算の処理がどこにあるか調査して
    Claude に入力
    average 関数の挙動を調べて
    Claude に入力
    percentOf はどこから呼ばれてる？
    Claude に入力
    テストが足りていない関数を調査して
    Claude に入力
    NaN になる原因を調べて
    期待する結果　[investigate 起動] が出ないことが多い。この教材での確認では「調査して」と言っても起動しなかった。

    1本ごとに、新しいセッション（/clear）で試すのが望ましい。起動した本数を数える。

  2. 短い description の Skill に、レビューを頼む

    Claude に入力
    sample/src/calculator.ts をレビューして
    期待する結果　local-review は、description に「レビュー」の語が入っているため、短くても起動することがある。

    語が一致すれば当たることもあるが、安定しない。「何をするか＋いつ使うか＋使わない場面」を書くと安定する。

  3. Claude に description を採点させる（付録 ③）

    Claude に入力
    .claude/skills/ の全 Skill の description を、次の観点で採点して。
1. 何をするか / いつ使うか / トリガー語の3点が揃っているか
2. 三人称の平叙文になっているか
3. 他の Skill と説明が重なっていないか
低評価のものは書き直し案を出して。まだ適用しないで。
    期待する結果　investigate は低評価になり、書き直し案が出る。

  4. 自分で直して、再テストする

    期待する結果　answer/investigate-good.md を参考に、.claude/skills/investigate/SKILL.md の description を書き換える。新しいセッションで、手順 1 の5本をもう一度試し、起動する本数が増えたか比べる。

    編集は再起動なしで反映される。ただし同じ会話は前の文脈が残るので、必ず新しいセッションで試す。

  5. 対象外の依頼でも試す（呼ばれすぎの確認）

    Claude に入力
    average に空配列チェックを追加して
    Claude に入力
    README を書いて
    期待する結果　直した investigate が、修正や文書作成の依頼では起動しないこと。起動したら「使わない場面」の一文を足す。

整理

書き方の規則理由
三人称・平叙文で書く（「〜する。〜のときに使う」）description はシステムプロンプトに入る。視点が混ざると判断が不安定になる
利用者が実際に打つ言葉を入れる照合は言葉ベース。日本語で頼むなら日本語のトリガー語を含める
「使わない場面」も書く似た Skill との競合・過剰な呼び出しを防ぐ
1,024 文字以内（目安 200 字前後）長いと切り詰められる。トリガー語は先頭に

ここがポイント

  • 改善サイクル: description を書く → 言い換えた依頼を 5〜10 本試す → 呼ばれない：トリガー語を足す／呼ばれすぎ：否定条件を足す → 再テスト（P7・P9）。
  • 目標の目安: 呼ばれるべき 10 本のうち 9 本以上、対象外 5 本は誤って呼ばれない（P9）。

うまくいかないとき

  • 結果が安定しない → 同じ依頼を 3 回繰り返して判断する。1 回では判断しない。

LLM の判断で動くため、結果は毎回同じとは限らない。「期待する結果」はこの教材で確認した例。違う結果になっても、言い換えて何度か試す。
