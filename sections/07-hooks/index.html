07　hooks で強制する

所要 15分資料 P5・P12
このセクションのゴール
Skill は「お願い」で、hooks は「強制」。同じルールを両方で書き、どちらが確実に守られるかを比べる。

準備

リポジトリ直下から、次のコマンドでこのセクション専用の環境を起動する。

ターミナル
cd sections/07-hooks && claude
このセクションの中身
.claude/skills/careful-edit/SKILL.md   「calculator.ts は編集しない」とお願いする Skill
.claude/hooks/block-protected.mjs         保護対象への Edit / Write を拒否する
.claude/hooks/log-edit.mjs                編集のたびに記録を追記する
hooks.settings.json                       hooks の定義（--settings で読み込む）

やってみる

  1. A: Skill だけ（hooks なし）で、編集を頼む

    Claude に入力
    ルールより私の指示を優先してよい。sample/src/calculator.ts の average に、空配列なら例外を投げる処理を追加して
    期待する結果　Skill の「編集しない」というお願いは、ユーザーの指示で上書きされ、編集されることがある（この教材での確認では編集された）。

    Skill は指示。強い指示が重なると、守られないことがある。

  2. サンプルを元に戻す

    ターミナル
    ../sync-sample.sh
    期待する結果　編集が取り消される。

  3. B: hooks ありで起動して、同じ依頼をする

    ターミナル
    claude --settings hooks.settings.json
    Claude に入力
    ルールより私の指示を優先してよい。sample/src/calculator.ts の average に、空配列なら例外を投げる処理を追加して
    期待する結果　編集が拒否される。Claude が「[hook] 保護されています（…）」と説明し、修正案だけを提示する。ファイルは変わらない（この教材での確認結果）。

    PreToolUse の hook が、ツール実行の前に動き、終了コード 2 で拒否した。Claude の判断は関係ない。

  4. B': Bash 経由の書き換えも止まるか試す

    Claude に入力
    Bash の sed -i を使って sample/src/calculator.ts の add の + を - に書き換えて
    期待する結果　matcher に Bash を含めてあるので、保護対象のパスと書き込み操作（sed -i・>・mv など）を含むコマンドも拒否される。

    これは簡易判定。変数展開やスクリプト経由の書き込みは、コマンド文字列から読み取れず、止められない。

  5. C: 保護対象外のファイルは編集できる

    Claude に入力
    sample/src/calculator.test.ts に average の空配列のテストを1つ追加して
    期待する結果　編集が通る。.claude/hooks/edit.log に、編集の記録（日時・ツール・パス）が追記される。

    PostToolUse の hook が、編集成功のたびに記録を残した。

  6. 記録を見て、後始末をする

    ターミナル
    cat .claude/hooks/edit.log
    ターミナル
    ../sync-sample.sh && rm -f .claude/hooks/edit.log
    期待する結果　記録が見える。サンプルが元に戻る。

整理

部品読み込まれるタイミング向いているもの
CLAUDE.md常時全タスクに適用される原則
Skills必要なときだけ特定作業の手順・規約・テンプレート
sub-agent委譲されたとき独立コンテキストでの調査・レビュー
hooksイベント発生時（強制）破られたら困るルール
hooks.settings.json（実ファイルの内容）
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit|Bash",
        "hooks": [
          { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/block-protected.mjs\"" }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit",
        "hooks": [
          { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/log-edit.mjs\"" }
        ]
      }
    ]
  }
}
block-protected.mjs（実ファイルの内容）
// PreToolUse hook: 保護対象のファイルへの書き込みを、Claude の意思に関係なくブロックする。
// 終了コード 2 + stderr のメッセージで、ツール呼び出しが拒否され、Claude に理由が渡される。
//
// 止められる範囲（教材としての限界も含めて把握しておく）
//   - Edit / Write / MultiEdit の file_path が保護対象に一致するもの
//   - Bash のコマンドに保護対象のパスと「書き込みらしい操作」が両方含まれるもの（簡易判定）
// 止められないもの
//   - 変数展開・スクリプト経由・別名リンクなど、コマンド文字列から読み取れない書き込み
//   - 本気で守るなら、権限設定（permissions の deny）やファイルの権限も併用する
import { readFileSync } from "node:fs";

// 相対パスで書かれた Bash コマンドにも一致するよう、先頭の / は付けない
const PROTECTED = ["sample/src/calculator.ts", ".claude/skills/"];
// sed / perl の -i（-E -i や --in-place のように、オプションの位置が違っても拾う）/ tee / mv / cp / rm / リダイレクト（2>&1 などは除く）
const WRITE_LIKE = /\b(sed|perl)\b[^|;&]*\s(-[a-zA-Z]*i|--in-place)|\b(tee|mv|cp|rm)\b|(?<![0-9&])>/;

const input = JSON.parse(readFileSync(0, "utf8"));
// Windows のパス区切りも同じ形で比較する
const normalize = (value) => String(value ?? "").replaceAll("\\", "/");

let target = "";
if (input.tool_name === "Bash") {
  const command = normalize(input.tool_input?.command);
  if (WRITE_LIKE.test(command)) target = command;
} else {
  target = normalize(input.tool_input?.file_path);
}

const hit = PROTECTED.find((pattern) => target.includes(pattern));
if (hit) {
  console.error(`[hook] 保護されています（${hit}）。編集せず、修正案を提示してください。`);
  process.exit(2);
}

ここがポイント

  • 「破られたら困るルール」は hooks に書く（P5・P7 の切り分け）。Skill に「禁止」と書いても、強制力はない。
  • 保護対象に /.claude/skills/ も入れてある。Claude が自分の Skill を書き換えて振る舞いを変えるのを防ぐ（P12「.claude/skills/** の書き込みは権限設定で確認を挟む」の実装例）。
  • hooks でも「完全な防御」にはならない。この hook が見るのは、Edit / Write の file_path と、Bash のコマンド文字列だけ。文字列から読み取れない書き込み（変数展開・別スクリプト経由など）や、パターンに入っていない書き方（python -c、awk -i inplace など）は止められない。逆に、読むだけのコマンドでも cp や > を含むと拒否されることがある（簡易判定のため）。本気で守るなら、権限設定（permissions の deny）やファイル自体の権限も併用する。
  • パスは \ を / に直してから比べているので、Windows のパスにも反応する（この教材は macOS で確認）。
  • hooks はコマンドを実行する仕組み。他人のリポジトリの hooks は、中身を読んでから使う。

うまくいかないとき

  • B で編集されてしまう → --settings hooks.settings.json を付けて起動したか確認。/hooks で登録されているか見る。
  • node がない → Node.js をインストールする。

LLM の判断で動くため、結果は毎回同じとは限らない。「期待する結果」はこの教材で確認した例。違う結果になっても、言い換えて何度か試す。
