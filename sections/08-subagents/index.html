08　sub-agent と並行実行

所要 15分資料 P5・P10
このセクションのゴール
Skill から sub-agent を呼び、レビューと調査を並行で走らせる。Skill を sub-agent に渡す方法（skills:）も確かめる。

準備

リポジトリ直下から、次のコマンドでこのセクション専用の環境を起動する。

ターミナル
cd sections/08-subagents && claude
このセクションの中身
.claude/agents/
├── reviewer.md            レビュー担当（skills: review-rules）
└── investigator.md        調査担当（skills: investigate-rules）
.claude/skills/
├── review-rules/          レビュー観点（人は呼べない。sub-agent に事前注入）
├── investigate-rules/     調査の進め方（同上）
└── parallel-check/        手動専用。2 つを同時に起動してまとめる

やってみる

  1. sub-agent と Skill を確認

    Claude に入力
    /agents
    Claude に入力
    /skills
    期待する結果　reviewer と investigator が見える。parallel-check が Skill として見える。

  2. 並行チェックを呼ぶ

    Claude に入力
    /parallel-check sample/src/calculator.ts
    期待する結果　[parallel-check 起動] のあと、reviewer と investigator の 2 つが同時に起動する（この教材での確認では 2 つとも起動した）。最後に「並行チェック結果」として、レビュー・調査・総合所見が 1 枚にまとまる。

    2 つの結果は、それぞれの sub-agent の独立したコンテキストで作られ、要約だけが親の会話に戻る。親の会話が散らからない。

  3. Skill が sub-agent に渡っているか確かめる

    Claude に入力
    reviewer に、sample/src/calculator.ts をレビューさせて
    期待する結果　reviewer の回答の先頭に [reviewer: review-rules 適用] が出ることがある。skills: に書いた Skill の全文が、起動時に sub-agent へ注入されている。

    親が要約して返すときにマーカーが省かれることもある。

整理

Skill → sub-agent（この節）context: fork（06）
向きsub-agent の定義側が Skill を持つ（skills:）Skill 側が sub-agent を指定する（agent:）
使いどころ役割（レビュー担当など）に、規約を持たせたい1 つの調査手順を、独立して実行したい
並行実行親が複数を同時に起動できる1 つの Skill につき 1 つ

ここがポイント

  • disable-model-invocation: true の Skill は、skills: では sub-agent に渡せない（P5）。そのため手動専用の parallel-check は、渡す側ではなく、sub-agent を呼ぶ側にしてある。渡す側の review-rules などは user-invocable: false の背景知識にしている。
  • tools: Read, Grep, Glob で、sub-agent に使わせるツールを読み取り専用に絞っている。
  • 独立した作業は並行にできるが、同じファイルを編集する作業を並行にすると衝突する。今回は両方とも読み取り専用。

うまくいかないとき

  • 2 つが順番に動く → parallel-check の本文に「同じターンで同時に」と書いてある。それでも順番になるときは、もう一度頼む。
  • /agents に出ない → このディレクトリで起動しているか確認。

LLM の判断で動くため、結果は毎回同じとは限らない。「期待する結果」はこの教材で確認した例。違う結果になっても、言い換えて何度か試す。
