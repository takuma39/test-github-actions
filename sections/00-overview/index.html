Skills ハンズオン / セクション 00

00　全体像と進め方

資料 P1〜P5
このセクションのゴール
Skills が何で、どこに置かれ、どう読み込まれるかを、実際の画面で確かめる。以降のセクションの前提をそろえる。

準備

このセクションは main ブランチで進める。

ターミナル
git switch main

前のセクションで書き換えたファイルがあると、切り替えに失敗したり、変更が持ち越されたりする。git restore . で元に戻してから切り替える。切り替えたあとは、新しい会話（新しいセッション）で Claude Code を開く。

このセクションの中身（.claude/ など）
.claude/skills/pr-review/SKILL.md   main にだけある、CI 用の Skill
sections/                                各セクションの手順書と、.claude/ の元データ
sample/                                  全セクション共通の題材（電卓）

やってみる

  1. ブランチの一覧を見る

    ターミナル
    git branch -a
    期待する結果　main と、section-01-auto-invoke のような section-… のブランチが並ぶ。

    どのブランチも、.claude/ 以外は同じ内容。ブランチを切り替えると、.claude/（Skill・hooks・設定）だけが入れ替わる。

  2. 見えている Skill を一覧する

    Claude に入力
    /skills
    期待する結果　pr-review（Project）だけが見える。main の .claude/ には、CI 用の pr-review しか置いていない。個人設定やプラグインの Skill が混ざって見えることもある。

    セクションのブランチに切り替えると、/skills に、そのセクションの Skill が出る。いま何が見えているかは、いつでも /skills で確認できる。

  3. 常時読み込まれているものを見る

    Claude に入力
    /context
    期待する結果　Skills の欄に、name と description だけが載っている（本文は載っていない）。

    これが「3層ロード」の Level 1。Skill を増やしても、常時読み込まれる量はわずか。本文は Claude が必要と判断したときに初めて読まれる（Level 2）。

ここがポイント

  • Skill は <名前>/SKILL.md を含むフォルダ。.claude/skills/ に置けば、そのプロジェクトの全員が使える（Git で共有）。
  • この教材はブランチで教材を切り替える。main が目次・手順書・題材・CI を持ち、section-… ブランチは .claude/ の中身だけが違う。
  • 同名の Skill は Enterprise > Personal > Project の順で優先される（P5）。
  • 「全作業で要るか？」が No なら Skill にする。全作業で要るなら CLAUDE.md、強制したいなら hooks（セクション 07）。

うまくいかないとき

  • claude コマンドがない → Claude Code をインストールする。VS Code 拡張を使う場合は、拡張で新しい会話を開く。
  • Skill が一覧に出ない → git branch --show-current で、いまのブランチを確認する。
  • ブランチを切り替えたのに前の Skill が見える → 新しい会話で開き直す。

LLM の判断で動くため、結果は毎回同じとは限らない。「期待する結果」はこの教材で確認した例。違う結果になっても、言い換えて何度か試す。
