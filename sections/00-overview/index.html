Skills ハンズオン / セクション 00

00　全体像と進め方

所要 10分資料 P1〜P5
このセクションのゴール
Skills が何で、どこに置かれ、どう読み込まれるかを、実際の画面で確かめる。以降のセクションの前提をそろえる。

準備

リポジトリ直下から、次のコマンドでこのセクション専用の環境を起動する。

ターミナル
cd sections/00-overview && claude
このセクションの中身
sections/
├── 00-overview/         ← いまここ（.claude/ なし）
├── 01-auto-invoke/      各セクションが自分専用の .claude/ を持つ
│   ├── .claude/skills/
│   └── sample/          題材（電卓）のコピー
└── ...
.claude/skills/pr-review/   ← リポジトリ直下。CI 用。全セクションに継承される

やってみる

  1. 見えている Skill を一覧する

    Claude に入力
    /skills
    期待する結果　リポジトリ直下の pr-review（Project）が見える。あなたの個人設定やプラグインの Skill も混ざって見えることがある。

    セクション 01 以降では、そのセクションの Skill が増える。どの Skill が見えているかは、いつでも /skills で確認できる。

  2. 常時読み込まれているものを見る

    Claude に入力
    /context
    期待する結果　Skills の欄に、name と description だけが載っている（本文は載っていない）。

    これが「3層ロード」の Level 1。Skill を増やしても、常時読み込まれる量はわずか。本文は Claude が必要と判断したときに初めて読まれる（Level 2）。

ここがポイント

  • Skill は <名前>/SKILL.md を含むフォルダ。.claude/skills/ に置けば、そのプロジェクトの全員が使える（Git で共有）。
  • 親ディレクトリの .claude/skills/ は、子ディレクトリで起動しても読み込まれる。逆に、親で起動しても子の Skill は見えない（この教材の検証結果）。だから各セクションは、それぞれのディレクトリで claude を起動する。
  • 同名の Skill は Enterprise > Personal > Project の順で優先される（P5）。
  • 「全作業で要るか？」が No なら Skill にする。全作業で要るなら CLAUDE.md、強制したいなら hooks（セクション 07）。

うまくいかないとき

  • claude コマンドがない → Claude Code をインストールする。
  • Skill が一覧に出ない → 起動したディレクトリを確認する（pwd）。

LLM の判断で動くため、結果は毎回同じとは限らない。「期待する結果」はこの教材で確認した例。違う結果になっても、言い換えて何度か試す。
