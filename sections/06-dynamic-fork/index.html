06　動的コンテキストと fork

資料 P10
このセクションのゴール
Skill の中でコマンドを実行して結果を埋め込む !`cmd` と、別コンテキストで動かす context: fork を確かめる。

準備

プロジェクトルートから、次のコマンドでこのセクション専用の環境を起動する。

ターミナル
cd sections/06-dynamic-fork && claude
このセクションの中身
.claude/skills/
├── summarize-changes/SKILL.md   !`git diff HEAD --stat` で差分一覧を埋め込む
└── repo-survey/SKILL.md         context: fork + agent: Explore
sample/

やってみる

  1. （準備）差分を作る

    ターミナル
    echo '// 学習用メモ' >> sample/src/calculator.ts
    ターミナル
    git diff HEAD --stat -- .
    期待する結果　変更ファイルが 1 件表示される。この教材のサンプルが Git に取り込まれていることが前提（未取り込みだと差分が空になる）。

  2. 差分の要約を頼む

    Claude に入力
    変更を要約して
    期待する結果　[summarize-changes 起動] が出る。要約は、Skill を読み込んだ時点でシェルが実行され、その出力が本文に埋め込まれた状態から始まる。

    Claude が git を実行したわけではない。Skill が読み込まれる前処理で、!`git diff HEAD --stat` が実行されて置き換わる。差分全体ではなく一覧だけを埋め込むのがコツ（巨大化や .env の混入を防ぐ）。

  3. fork で調査する

    Claude に入力
    /repo-survey
    期待する結果　[repo-survey 起動 / fork] が出て、ディレクトリごとの役割の表が返る。途中経過は書かれず、結果だけが戻る。

    context: fork の Skill は、親の会話履歴を持たない独立したコンテキストで実行され、結果だけが戻る。手順が完結した「調査系」向き。背景知識だけの Skill には意味がない。

  4. 後始末

    ターミナル
    ../sync-sample.sh
    期待する結果　サンプルが元に戻る。

ここがポイント

  • allowed-tools: Bash(git diff *) は、その Skill を呼び出したターンに承認なしで使えるツールを宣言するもの。他ツールの禁止ではない（P10）。
  • !`cmd` は注入の経路にもなる。外部由来の Skill では使わない（セクション 11）。

うまくいかないとき

  • 差分が空と言われる → 準備の手順を実行したか、サンプルが Git に取り込まれているか確認する。

LLM の判断で動くため、結果は毎回同じとは限らない。「期待する結果」はこの教材で確認した例。違う結果になっても、言い換えて何度か試す。
