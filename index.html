Claude Code Skills ハンズオン

手を動かしながら、Skills・hooks・sub-agent・MCP を順に確かめる教材。各セクションが自分専用の .claude/ を持つので、cd して claude を起動するだけで、そのセクションの Skill だけが見える。

進め方
1. このリポジトリを clone し、リポジトリ直下で pnpm install（09 で使用）
2. 下の一覧から、セクションの「cd」をコピーして、ターミナルに貼り付ける
3. claude を起動し、「手順書を開く」の手順を、上から順に進める

セクション一覧

00全体像と進め方10分手順書を開く →

Skills が何で、どこに置かれ、どう読み込まれるかを、実際の画面で確かめる。

ターミナル
cd sections/00-overview
01自動で呼ばれる（/ なし）10分手順書を開く →

Skill の名前を言わずに「レビューして」「調査して」と頼むだけで、Claude が適切な Skill を選んで使うことを確かめる。

ターミナル
cd sections/01-auto-invoke
02/ で呼ぶ（手動）8分手順書を開く →

同じ Skill を、/名前 で明示的に呼ぶ。

ターミナル
cd sections/02-slash-invoke

description の書き方で、Skill が呼ばれるかどうかが変わることを体験する。

ターミナル
cd sections/03-description
04呼び出しの制御15分手順書を開く →

Skill を「誰が呼べるか」で使い分ける。

ターミナル
cd sections/04-invocation-control
05scripts で検査を自動化15分手順書を開く →

「文章で守れ」と書いても守られないルールを、スクリプトで機械的に判定させる。

ターミナル
cd sections/05-scripts

Skill の中でコマンドを実行して結果を埋め込む !`cmd` と、別コンテキストで動かす context: fork を確かめる。

ターミナル

07hooks で強制する15分手順書を開く →

ターミナル

Skill から sub-agent を呼び、レビューと調査を並行で走らせる。

他人の Skill を取り込む前の監査を体験する。

ターミナル
cd sections/11-safety

前提

  • Claude Code が使えること（ログイン済み）
  • Node.js 22 以上、pnpm（09 の画面確認で使う）、Python 3（05・11）、Node.js（07 の hook）
  • リポジトリ直下の .claude/skills/pr-review は CI 用。全セクションに継承されるので、/skills に常に見える
  • 題材は電卓（sections/_sample/）。学習用に、わざと不備を入れている（average([]) が NaN、percentOf(x, 0) が Infinity、parseNumber("abc") が NaN、テストが正常系だけ。一覧は 01 にもある）。変更した後は sections/sync-sample.sh で元に戻せる

おすすめの順番

最初に 00 → 01 → 02 → 03 で基本（自動と手動、description）をつかむ。そのあとは興味のあるものから。07（hooks）と 08（sub-agent）、09（ブラウザ打鍵）は、01〜03 を終えてからが分かりやすい。

資料: 「Skills 入門」（社内共有用 PDF）。各ページの「資料 P○」は、その PDF のページ番号。
